# Blender → Caustica 场景同步与渲染实施方案

版本：0.3 · 日期：2026-10-10 · 状态：可选实时同步方案，尚未实现

> 2026-10-10 范围调整：当前主流程为“多视角参考 → 完全在 Blender 中完成几何 → 文件导出 → Caustica Scene Fit 仅拟合材质与灯光”。建模阶段无需 Caustica 同步。本文保留为以后需要交互预览时的可选方案，不再作为首版任务或多视角建模的前置条件。当前实现与使用方式见 [多视角拟合工具](multiview-fitting.md)。

## 1. 可选实时同步目标

用户在 Blender 中建模 Mesh，通过同步插件和本地进程通信，将几何、物体变换及按需选择的相机、基础材质与灯光同步到 Caustica Editor 进程，在 Editor 中渲染并查看结果。

首版交付标准是“Blender 建模 → IPC 同步 → Caustica Editor 查看渲染结果”。Blender 插件只需提供连接与同步功能，不要求注册 RenderEngine 或回传图像。不要求图片重建、自动建模、AI 优化或 Blender 实时渲染视口；这些属于后续扩展。Caustica 不开发挤出、布尔、细分、雕刻等建模工具。

以下内容仅描述选择实现实时同步时的工作范围；当前文件交接与外观拟合不依赖该开发顺序。[多视角拟合方案](ai-multiview-reconstruction-plan.md)保留联合几何优化的后续研究需求。

## 2. 架构

```text
Blender 同步插件                     Caustica Editor 进程
读取 evaluated scene                接收、校验并应用场景
对象/资产 ID 与版本                  管理渲染场景与 GPU
场景编码与同步请求   ← 本地 IPC →     等待资源就绪并渲染
显示连接状态、同步进度与错误         在 Editor 视口显示结果
```

Blender 是同步对象几何的来源，Caustica Editor 维护用于渲染的镜像。几何保存与修改器编辑继续使用 `.blend`；Caustica 接收计算后的三角形 Mesh，不需要重现 Blender 修改器逻辑。

Editor 使用独立的 Blender 同步根节点管理导入对象。默认同步几何、物体变换和材质绑定，Editor 的观察相机与灯光保持本地控制；相机、材质参数、灯光分别提供可选同步开关。启用某类同步后，下一次同步以 Blender 数据覆盖该类导入数据。Editor 自建对象不受影响。同步对象的几何修改不回写 Blender，首版不做双向编辑。

首版优先全量替换同步根节点内的数据，并在 Editor 渲染。通信协议保留资产 ID/revision，为后续增量同步留接口，但不把增量更新作为首版前置条件。

## 3. 插件职责

- 提供 Caustica 连接/同步面板，首版由用户显式点击同步。
- 获取渲染依赖图中的最终几何，包含已计算的修改器、物体变换与可见实例。
- 导出相机、灯光、基础材质、纹理路径及渲染配置。
- 连接已启动的 Caustica Editor，管理请求 ID、同步进度、取消、超时与错误展示。
- 先冻结支持的 Blender 版本，并针对该版本验证 Python API。

不得直接从网络/IPC 工作线程访问 Blender 场景数据。临时 evaluated Mesh 应在复制数据后释放；跨线程和跨进程只传输自有数据。

## 4. 场景数据契约

协议应有 `protocol_version`、`session_id`、`request_id`、`scene_revision`。对象 ID 和资产 ID 在插件会话内稳定；重连后首版执行全量同步，不复用上次进程的 runtime handle。

| 数据 | 首版内容与规则 |
| --- | --- |
| Mesh | positions、三角形索引、法线、可选 UV、每三角形材质槽；声明 dtype、长度、字节序 |
| 物体 | 稳定 ID、mesh_id、局部到世界矩阵、可见性、材质绑定 |
| 相机 | 位姿、投影类型、内参/投影参数、裁剪范围、分辨率；明确裁剪与像素中心规则 |
| 材质 | 首版限定基础参数；使用 Caustica 专用参数面板或明确的节点映射子集 |
| 灯光 | 类型、位姿、颜色、强度、尺寸；明确单位和映射规则 |
| 世界 | 首版固定背景/环境参数，支持范围显式列出 |
| 渲染 | 分辨率、采样配置、输出格式、颜色空间、目标 scene_revision |

Blender 的 UV 和分裂法线可以按面角存储。传输前必须按渲染需要拆分顶点，保留 UV 接缝、硬边和材质槽，不能仅按位置顶点索引导出这些属性。三角化不得破坏属性对应关系。

明确 Blender 的 Z-up 到 Caustica 的 Y-up 转换、米制尺度和矩阵布局。非均匀缩放的法线变换、负缩放的面绕序/背面规则必须测试。相机匹配包含视角、sensor fit、shift 和图像宽高比；首版至少支持透视相机，暂不支持的投影必须明确拒绝。

不支持的材质节点、曲线/体积等对象类型或功能应返回具体提示，不能静默丢失。材质和灯光映射不保证与 Cycles 数值或外观完全相同。

## 5. IPC 与二进制传输

首版建议使用本机 TCP：控制信息用带长度前缀的 JSON，Mesh 使用二进制数据块，Editor 回传同步状态。Socket 是字节流，收发必须处理部分读写、分帧和断连，不能假设一次读取就是完整消息。

- 仅绑定 loopback，Editor 显式启用同步服务并生成会话 token，插件连接时校验 token 与协议版本。
- 大数组不使用逐顶点 JSON 或 Base64；元数据指定块 ID、dtype、shape、字节数，并限制消息和资源大小。
- 首版允许复制传输。共享内存作为性能优化，待测量后引入；届时必须定义生产/消费确认、句柄与资源释放。
- 首版图像留在 Editor 显示，无需图像传输；后续需要 Blender RenderEngine 或自动评估时再定义图像/AOV 传输与颜色空间契约。
- 纹理首版可引用双方可访问的绝对路径；Blender packed/generated 图片需先导出到会话目录或明确提示不支持。
- 不将 Blender 对象指针或 Caustica GPU handle 当作协议 ID。

建议最小消息集合：`hello`、`sync_scene`、`cancel`、`get_status`、`release_session`。这些是待实现的协议草案，不是现有接口。同步成功后由 Editor 正常渲染循环显示新场景。

## 6. Caustica 侧需要实现的工作

- Editor 同步服务入口：启用/关闭、监听地址、握手、日志和连接状态面板。
- 场景接收层：验证数组、引用、版本和资源限额，将请求排入引擎所属线程。
- 公共 Mesh 创建/替换入口：接收 normals/UV/material slots，更新 GPU、包围盒和加速结构。
- 对象、相机、基础材质/灯光的场景映射；不在 IPC 层直接操作 GPU。
- 场景应用完成与资源就绪确认；重置渲染累积并在 Editor 视口显示新版本。
- 同步进度、错误和取消；清理失败候选与会话资源，不依赖图像回传。

现有场景导入、EngineApp、MeshDeformApi、相机和捕获能力可作为基础，但不能据此声称已经支持任意内存 Mesh 创建或完整 Blender 场景映射。

首版可以使用项目私有中间资产完成应用，但不得通过整场景重载丢失 Editor 自建对象、相机或照明修改。若采用中间文件，必须保持法线、UV、材质槽一致，并将文件生命周期纳入任务管理。保存 Editor 场景时，应把仍被引用的临时资源迁移到持久目录，确保关闭同步连接后可以重新加载。

## 7. 任务完成语义

任务状态至少区分 queued/running/completed/failed/cancelled；“同步请求收到”不代表“资源可渲染”。同步完成必须返回成功应用且资源就绪的 scene_revision；Editor 显示该版本与是否正在累积，不把同步完成解释为图像已收敛。

首版每个 Editor 串行应用同步请求。收到重复 request_id 时明确拒绝或返回已有状态，不隐式重复执行。取消是尽力而为：回报实际状态并释放未提交资源。应用失败应保留上一有效同步场景。断连不删除已显示对象；重连后全量重同步同一导入集合，避免对象重复。

## 8. 开发阶段与验收

### B0：端到端通信原型

- [ ] 固定 Blender 版本，创建同步插件骨架和 Editor 同步服务。
- [ ] 实现握手、分帧、二进制传输和同步状态返回。
- [ ] 从 Blender 同步一个 Mesh、一台透视相机及基础照明，完成 Caustica 渲染。

验收：打开 Caustica Editor，在 Blender 点击同步后，Editor 显示导入 Mesh 的真实渲染结果；修改立方体尺寸并再次同步，Editor 中轮廓变化且版本更新。Blender 不需要显示渲染图。首版单机单连接即可。

### B1：可用的 Editor 同步插件

- [ ] 支持多对象、evaluated modifier Mesh、UV/分裂法线、材质槽和实例。
- [ ] 完成相机、基础材质/纹理、灯光与颜色空间转换。
- [ ] 完成取消、超时、断连恢复、不支持功能提示和资源清理。
- [ ] 提供安装说明、示例 `.blend` 和一条复现流程。

验收案例覆盖倒角/细分修改器、UV 接缝、硬边、多个材质槽、实例、非均匀/负缩放、可选同步的偏移透视相机。连续同步与重连不串用旧场景；无效数据被拒绝；Editor 中投影、朝向和颜色转换符合约定；本地相机/照明和自建对象按同步开关规则保留；保存后独立重开可正常渲染。

### B2：增量同步与交互预览

- [ ] 区分 transform、vertex、topology、material、light 更新与对象删除。
- [ ] 复用不变资产，合并快速编辑产生的过期更新。
- [ ] 增加 Blender 编辑变化监听、节流和自动同步，在 Caustica Editor 交互查看结果。

验收：同一场景增量结果与全量结果在渲染容差内一致；删除和拓扑变化不留下旧几何。性能目标在 B1 测量同步、上传、渲染和读回成本后制定。

### B3：可选 AI 与多视角拟合

在 B1/B2 的同步协议上扩展多相机任务、AOV、误差评估与 Agent 工具；AI 在 Blender 操作几何，Caustica 返回评估反馈。图片重建不是该阶段的必要条件。

## 9. 选择实时同步后的首个交付

若后续选择开发实时同步，以 B0 为起点：**一个 Blender Mesh 经 IPC 同步到 Caustica Editor，并在 Editor 中查看真实渲染结果**。先验证这一条路径，再扩展场景覆盖、增量和 AI。Blender RenderEngine、图像回传和独立无界面 worker 均为可选后续能力。当前主流程使用文件导出，不以 B0 为前置任务。
