# Caustica AI 多视角建模与外观拟合实施方案

文档版本：0.1 · 日期：2026-10-07 · 状态：需求与实施基线

> 2026-10-10 范围调整：根据多视角参考的几何建模完全在 Blender 中完成，完成后导出模型。Caustica 导入固定几何，使用 [Scene Fit](multiview-fitting.md) 调整材质、灯光并验证保留视角。建模阶段不需要 IPC 或 Caustica 实时同步。下文的联合几何优化、公共建模接口和 P0–P5 顺序保留为后续研究规划，不作为当前首版任务；默认外观拟合不搜索几何和相机。

本文规定后续开发的目标、模块边界、实施顺序和验收方式。除“现有基础”明确列出的能力外，本文的接口、格式和任务均为待实现设计，不代表当前已经可用。实施中如需调整范围，应同步更新本文和对应验收项。

## 1. 最终目标

用户提供同一个物体的多视角参考图，系统自动生成或导入初始 Mesh，在 Caustica 中渲染，并反复修改 Mesh 几何、材质和灯光，使多个视角下的渲染结果接近参考图。最终输出可编辑、可复现的资产与场景，为后续 Sim2Real 提供视觉模型基础。

核心闭环：

```text
参考图 + 相机/尺度信息
          ↓
初始 Mesh + 材质 + 灯光
          ↓
Caustica 按参考相机渲染
          ↓
轮廓 / 深度 / 法线 / RGB 比较
          ↓
AI 决策 + 数值优化
          ↓
修改几何 / 材质 / 灯光 → 再渲染
          ↓
验证视角通过 → 导出最佳资产与复现记录
```

系统必须支持三类实际修改：

- **几何**：整体尺寸、局部结构、顶点位置，后续扩展到拓扑与细分。
- **材质**：颜色、粗糙度、金属度及适用的 OpenPBR 参数，后续扩展纹理。
- **照明**：灯光位置、方向、强度、颜色、尺寸以及环境光。

第一阶段不以完整 Blender 式交互编辑器为目标，也不以单张图的视觉相似代替多视角几何正确性。大模型必须实际调用几何与外观工具，不能只生成建模说明。

## 2. 首版范围与输入条件

首版聚焦单个静态刚性物体，优先选择不透明、非强镜面、结构较简单、背景可分割的对象。支持基本体组合、已有 Mesh 和已知 CAD 作为初始模型；从图片直接生成任意复杂拓扑属于后续能力。

参考数据要求：

- 所有图片对应同一个物体状态；记录每张图的尺寸、相机内参和位姿。
- 提供前景 mask；深度、法线和特征对应关系可选，缺失时不启用相应误差项。
- 至少提供一个可靠的真实尺寸或尺度约束。单凭未标定照片不能保证恢复真实尺寸。
- 明确图片是否已去畸变、颜色空间、曝光与白平衡处理方式。
- 首版优先使用已标定或人工确认的相机，自动相机估计单独作为后续模块。
- 默认参考图来自固定照明条件。转台拍摄需明确每张图的物体姿态与灯光所在坐标系；照明改变的数据必须显式分组。

默认准备不少于 6 个覆盖不同方向的视角，其中至少 2 个作为保留验证视角。该数量是首版数据建议，实际覆盖范围比数量更重要。保留视角不参与参数搜索或候选选择。

首版不承诺恢复图片中不可见的内部结构，不承诺唯一恢复真实 BRDF 或真实灯光。透明、半透明、强反射、细毛发、可变形物体、动态照明及复杂遮挡列入后续专题。

## 3. 现有基础与主要缺口

现有接口以 [公共 API](public-api.md)、[宿主 API](../caustica.md) 和 [Agent 场景编辑基础](agent-authoring.md) 为准。

| 模块 | 现有基础 | 本项目需要补充 |
| --- | --- | --- |
| 场景编辑 | SceneDocument：持久 ID、批量事务、revision、undo/redo、保存；运行时场景查询 | 拟合项目、参数绑定、候选版本管理 |
| 发布到引擎 | 保存后显式 set_scene 并等待加载 | 统一应用/等待/捕获状态；后续增量更新 |
| 几何 | 已有 Mesh 变形和三角形更新入口，模型导入与内置基本体 | 公共 Mesh 创建/替换/保存接口、校验、参数化建模、局部变形 |
| 外观 | OpenPBR、灯光与环境设置相关能力 | 可查询的参数 schema、边界与批量修改、外部材质/纹理资产快照 |
| 观测 | 相机内参/位姿、多个相机与 RGB/depth/normal/ID 等 AOV | 参考数据导入、投影一致性验证、误差计算与对照报告 |
| AI | 与模型供应商无关的 Python 编辑基础 | 工具适配器、运行器、优化器与恢复机制 |

现有 SceneDocument 的历史只覆盖文档及资源绑定，不覆盖外部 Mesh、材质和纹理文件内容；发布目前会重载场景，也未与编辑器 UI 的 undo 同步。因此，不能直接把现有 undo 当作完整拟合实验回滚。

## 4. 模块与责任边界

### 4.1 Caustica C++ 核心

负责可靠地创建/修改几何、应用材质灯光、执行渲染、输出 AOV、保存资产。公开接口应具有明确的线程归属、资源生命周期和完成语义；网络请求不得直接修改 ECS 或 GPU 数据。

几何更新必须正确处理包围盒、法线/切线、GPU buffer、光线追踪加速结构、时域历史及累积重置。顶点修改和拓扑修改应区分：前者可能允许 refit，后者需要按实际资源变化重建。

### 4.2 Python 拟合运行器

负责参考项目、参数向量、相机配置、阶段控制、调用引擎、误差评估、候选与最佳版本、日志、预算、暂停/取消和恢复。首版优化与图像评估优先放在 Python，避免把模型 SDK 和优化框架放进渲染核心。

### 4.3 大模型 Agent

负责识别物体结构、选择初始模型、规划建模操作、选择参数组、分析多视角结果、提出结构修改。调用统一工具协议；GPT、DeepSeek 等供应商接在适配层。

大模型不负责逐个猜测海量顶点坐标。结构选择和离散修改由 Agent 主导，受约束的连续参数交给数值优化；图像反馈和结构化误差共同用于决策。

### 4.4 几何初始化适配器

允许接入外部重建/图像到 3D 工具，但输出必须转为可编辑 Mesh，并经过尺度、坐标、法线、材质槽和几何有效性检查。外部服务不是首版闭环的必需依赖，先使用基本体或已有模型验证。

## 5. 数据与接口契约

以下是目标格式与语义，具体字段在对应阶段实现时冻结并增加版本号。

### 5.1 拟合项目

建议项目目录：

```text
project/
  project.json             # schema_version、单位、坐标、输入和约束
  references/              # 图片、mask、可选 depth/normal
  assets/                  # 初始及最终 mesh/material/texture
  scene/                   # Caustica 场景与相机
  runs/<run_id>/
    config.json            # 参数边界、阶段、优化器、预算、渲染配置
    iterations.jsonl       # 每轮参数、状态、误差、耗时和产物引用
    candidates/            # 候选快照与渲染
    best.json              # 当前最佳有效候选
    report/                # 最终多视角对照与误差报告
```

每个参考视角记录 `view_id`、`split`、图片路径、分辨率、内参、位姿、畸变/去畸变状态、mask、可选深度与有效像素定义。深度必须注明轴向深度或射线距离、单位和无效值；法线必须注明空间与编码。

相机导入时显式转换到 Caustica 的约定：右手系、+Y 向上、米；相机局部 +X 向右、+Y 向上、朝 -Z；图片原点在左上。外参统一选定 camera-to-world 或 world-to-camera，并明确矩阵布局，禁止靠字段名称猜测。

用已知 3D 点投影的测试固定像素中心、内参缩放/裁剪、坐标变换及深度约定。参考图与渲染必须按相同几何变换对齐。

### 5.2 Mesh 操作

拟提供 `create_mesh`、`get_mesh_info`、`replace_mesh`、`update_vertices`、`save_mesh` 等工具；这些名称为设计草案，不是现有 API。

- 输入包含稳定资产 ID、预期 revision、坐标空间、位置、三角形索引、可选 normal/UV/material slot。
- 拒绝非有限值、索引越界、属性数量不一致、超限资源；退化面采用明确的拒绝或清理策略并返回报告。
- 局部顶点编辑限定拓扑不变；拓扑编辑返回旧索引/选择集是否失效的信息。
- 共享 Mesh 默认复制为项目私有资产后修改；修改共享资产必须明确声明影响范围。
- 增加参数化基本体与组合结构，参数必须具名、带单位、边界和依赖；首版优先优化这些低维参数。
- 后续增加控制笼/局部变形、挤出、细分及重网格，避免首版直接无约束优化全部顶点。

### 5.3 材质、灯光与参数绑定

公开可查询的参数 schema：类型、单位、范围、颜色空间、可写性、关联资源。使用稳定实体/材质槽/资产 ID 绑定，不能依赖 GPU 索引或跨场景加载失效的 runtime handle。

参数组至少包括几何、相机、材质、灯光；每组支持锁定、上下界和先验。首版固定曝光/色调映射及白平衡，避免把曝光漂移当作拟合进展。所有角度字段按实际接口约定标注，不能假设一律为弧度。

外部资源使用项目私有副本与不可变候选快照；回滚必须恢复几何、材质、灯光、相机和渲染配置，而非仅恢复场景 JSON。

### 5.4 操作状态与产物归属

请求包含 `request_id`、项目/运行 ID 和预期版本；返回状态、错误、产生的版本和资源 ID。长操作支持 queued/running/completed/failed/cancelled，以及可查询的 job ID。

“修改提交完成”“GPU 更新完成”“场景加载就绪”“指定候选的捕获完成”是不同状态。每次评估必须等待对应状态完成，记录 document session/revision、资产版本、scene generation、相机、捕获帧和渲染配置；拒绝使用旧帧或前一个候选的图像。

运行器首版串行应用候选。`request_id` 仅作关联，现有 SceneDocument 不提供请求去重；重试前先查询结果，后续如实现幂等必须单独定义。

## 6. 渲染与误差评估

### 6.1 可比较的渲染

固定参考相机、分辨率、物体状态、背景策略、渲染器与曝光。记录采样数、降噪/时域设置、随机种子（若接口支持）及后端。几何或外观修改后重置必要历史，并完成预热后捕获。

比较路径应明确颜色转换：参考 sRGB 图片先按约定转为线性空间，或双方通过同一显示变换后比较；不能将线性 HDR 直接与显示 PNG 计算 RGB 误差。

同一候选重复渲染，测量噪声导致的指标波动；候选的改善必须超过噪声容差。最终候选采用更高质量复评，避免优化器利用低采样噪声。

### 6.2 误差项

| 误差 | 用途 | 启用条件 |
| --- | --- | --- |
| 轮廓 IoU / 轮廓距离 | 整体比例、形状和局部轮廓 | 前景 mask 可用 |
| 深度稳健误差 | 几何位置与表面形状 | 有标定、有效深度与尺度 |
| 法线角度误差 | 表面朝向 | 有可靠法线且空间一致 |
| 前景 RGB 稳健误差 | 外观、照明 | 颜色/曝光处理一致 |
| 特征或感知误差 | 补充结构与视觉判断 | 后续验证其适用性后启用 |
| 几何与参数正则项 | 防止畸形、过拟合和不合理参数 | 对应参数组启用 |

总目标为各视角归一化误差的加权和，加上几何与参数约束。缺失数据的误差项禁用，并重新规范化有效权重；不能把缺失值当零误差。

记录每个视角及每个误差项，不能只报告总分。遮挡、背景、有效深度和 mask 边界采用明确的有效像素规则。正则项至少考虑几何平滑、偏离初始形状幅度与退化面；封闭刚体按任务增加自交/封闭性检查。

## 7. 自动拟合流程

1. **输入校验**：检查路径、标定、视角分组、尺度和颜色处理；生成参考数据预览。
2. **基线**：导入或构造初始 Mesh，捕获所有视角，记录初始误差。
3. **相机/尺度对齐**：先人工确认或有限范围优化相机与物体位姿，再锁定大部分相机参数。
4. **粗几何**：采用中性材质，调整基本体尺寸、组合和整体比例，以轮廓和可用深度为主。
5. **细几何**：优化局部控制参数；需要拓扑改变时由 Agent 提出有限候选，分别评估。
6. **材质与灯光**：先采用受约束的少量材质与照明参数，按组优化，逐步开放自由度。
7. **联合微调**：在已收敛候选附近小范围调整；保留几何与外观正则约束。
8. **最终验证**：冻结候选后在保留视角评估，导出资产、场景、指标和复现报告。

首版采用无需渲染梯度的黑盒优化。先用坐标搜索等简单基线验证闭环；再根据参数维度、噪声和评估成本选择更合适的优化器。可微渲染是后续研究方向，不作为首版依赖。

停止条件包括最大迭代次数、渲染次数/时间预算、连续有效迭代改善不足、用户取消。运行结束总是保留最佳有效候选；失败、NaN 指标、无效几何和加载超时不应覆盖最佳版本。

几何、材质和照明存在多解：例如粗糙度与光源尺寸均影响高光。必须通过标定、锁定参数、先验和阶段顺序限制自由度。对仅凭输入无法确定的参数，报告采用的假设，不声称已恢复真实物理值。

## 8. 分阶段任务与验收

下列条目作为开发 backlog；完成后勾选并关联实现、测试和产物。每阶段先通过验收，再增加下一阶段自由度。

### P0：参考项目与可复现评估闭环

- [ ] 定义版本化项目 schema、相机转换与数据校验。
- [ ] 导入参考图片/mask/可选 depth，区分训练与验证视角。
- [ ] 实现固定配置的多视角捕获、版本归属及轮廓/RGB 评估。
- [ ] 输出并排图、叠加图、差异图和逐视角指标。
- [ ] 保存配置、候选和运行日志；失败后可重开项目。

验收：用 Caustica 合成已知物体和相机作为参考。相同配置复评得到噪声容差内的误差；人为扰动位姿/尺寸/颜色后相应指标变差。错误内参、深度约定和旧候选捕获可以被测试发现。此阶段允许已有 Mesh，不要求 AI 建模。

### P1：可编辑 Mesh 与参数化几何

- [ ] C++/Python 提供 Mesh 创建、替换、顶点更新、查询和资产保存。
- [ ] 校验输入并正确更新 GPU、包围盒、法线和加速结构。
- [ ] 支持具名基本体参数、组合物体以及项目私有 Mesh 副本。
- [ ] 提供完整候选快照/恢复，覆盖外部几何和材质资源。

验收：创建一个不依赖现成导入模型的 Mesh；改变尺寸与局部顶点后，各视角轮廓、深度和查询包围盒同步变化；保存重载一致；错误索引/非有限值拒绝且不破坏原资产；恢复候选后渲染回到允许误差范围。

### P2：无大模型的自动拟合基线

- [ ] 实现参数绑定、范围/锁定、阶段调度和黑盒优化器。
- [ ] 支持几何、材质、灯光分组优化及有限联合微调。
- [ ] 加入预算、取消、失败回退、断点恢复和最佳候选管理。
- [ ] 建立合成基准集与至少一个真实物体案例。

验收：对已知合成目标，从扰动参数出发自动改善几何与外观，并证明不依赖人工逐轮调整。至少使用 3 组固定初始化，报告初始/最终训练误差、保留视角误差、采样噪声、耗时与失败率。

建议首个简单合成案例的门槛：各有效视角 silhouette IoU ≥ 0.95，固定颜色处理后的前景 RGB MAE 相对初始值下降 ≥ 30%；同时报告尺寸误差，防止仅靠相机补偿。具体案例应在运行前冻结门槛；真实数据按标定质量单独制定，不能直接套用合成门槛。

### P3：接入大模型建模 Agent

- [ ] 定义供应商无关工具 schema、能力查询与结构化错误。
- [ ] 接入 GPT/DeepSeek 等工具调用适配器，凭据由宿主配置。
- [ ] 提供参考视角、当前渲染、差异图和结构化指标反馈。
- [ ] 支持 Agent 选择初始结构、调用几何工具、启动参数优化并恢复最佳候选。
- [ ] 记录工具调用、模型配置、预算和每次候选来源。

验收：从参考项目出发，Agent 自动构造/修改一个基本体组合物体，实际产生 Mesh 几何变化并执行材质/灯光优化，输出最终可重载资产及报告。全程无需人工逐轮指令；错误工具调用能够纠正或终止且保留有效结果。

### P4：复杂几何与纹理扩展

- [ ] 引入外部多视角重建或图像到 Mesh 初始化适配器。
- [ ] 支持局部控制笼、受约束变形、必要的拓扑操作。
- [ ] 支持 UV/纹理生成与优化，检查接缝和跨视角一致性。
- [ ] 建立更复杂对象的基准和几何质量报告。

验收：复杂对象在保留视角得到稳定改善，资产通过约定的几何有效性检查，能够继续编辑。不能只提交只适用于训练视角的贴图或不可编辑的渲染结果。

### P5：Sim2Real 资产准备

- [ ] 分离 visual mesh、collision mesh 与物理参数。
- [ ] 明确真实尺度、坐标、原点、装配关系和可选关节。
- [ ] 增加碰撞代理生成/校验及目标仿真系统导出。
- [ ] 为质量、惯量、摩擦等参数提供测量/标注入口和来源记录。

验收：视觉资产与碰撞资产坐标一致，尺寸可核对，目标仿真系统可加载并完成约定的落地/接触或装配测试。图像拟合成功只代表视觉阶段通过，不代表物理参数已经校准。

## 9. 工程验证与性能记录

- CPU 单元测试覆盖项目 schema、相机投影、误差有效像素规则、参数约束和快照恢复。
- GPU 集成测试覆盖 Mesh 更新后的轮廓/深度变化、资源就绪、累积重置和保存重载。
- 端到端合成测试使用已知几何与外观作为真值，防止只用自生成分数证明成功。
- 真实案例记录相机标定、照明条件、尺度依据和失败视角；不只展示最佳单张截图。
- 性能分别记录候选应用、GPU 更新/重载、预热、渲染、读回、评估和模型调用耗时；据此决定是否需要增量应用或并行评估。

不要求跨 GPU/驱动逐像素一致；项目必须记录运行环境，并针对噪声和后端差异定义可解释的容差。暂不承诺具体运行时间，完成 P0/P2 基准后再制定性能目标。

## 10. 首个开发切片与交付物

建议从 **P0 + P1 的最小纵向切片** 开始：一个已标定的合成物体、多个参考视角、一个具名尺寸参数、一次 Mesh 修改、一次多视角捕获、误差报告与完整回滚。随后扩展至 P2，让数值优化自动找回尺寸、基础材质和灯光参数，再接入 P3 的大模型。

每个可交付版本应包含：

1. 可打开的参考项目和输入说明。
2. 可编辑、可保存重载的 Mesh/材质/场景。
3. 初始、最佳候选及逐视角前后对照。
4. 训练与验证指标、失败原因、运行预算和环境记录。
5. 一条可复现的运行命令和对应验证步骤。

下一次开发默认从 P0 开始，不同时承担任意物体重建、完整 DCC 编辑器、可微渲染和完整物理系统。后续选择的数据集、外部重建工具、优化器和导出格式，均应在其阶段记录依据并更新本文。
